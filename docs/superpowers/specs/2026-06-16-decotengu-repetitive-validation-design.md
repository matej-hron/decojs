# decotengu Validation for the Repetitive-Dive Engine

**Date:** 2026-06-16
**Status:** Approved design, ready for implementation planning
**Depends on:** the repetitive-dive engine (`js/tripPlanner.js`, `js/decoModel.js` seam params), branch `feat/decotengu-repetitive-validation` (stacked on `feat/ndl-locked-dives`).

## Background & Motivation

The existing decotengu harness validates only **surface-saturated single dives**:
`scripts/generate_decotengu_reference.py` → `tests/decotengu-reference.json` →
`tests/decotengu-comparison.test.mjs` (standalone, run on demand — NOT part of the
`npm test` 262-test suite). Post-alignment agreement there is ~84% exact / 100% within
±1 min on the Bühlmann-air subset.

The repetitive engine adds physics that harness never exercises:
1. **Surface-interval off-gassing** — `simulateDepthTime(tissue, 0, gap, n2)` at the surface.
2. **Pre-saturated deco** — `generateDecoProfile` / `calculateNDL` started from a non-surface
   `initialTissuePressures` seed.
3. **The chaining glue** in `planTrip` that ties dives across surface intervals.

decotengu can validate all three: `model.load(abs_p, time, gas, rate, data)` advances tissue
pressures (replays a surface interval), `Data.tissues` exposes per-compartment N2/He pressures,
and the engine's `_dive_ascent` populates `engine.deco_table` from a seeded `Step` (computes
deco from a pre-saturated state). decotengu 0.14.1 is installed (`python3`, ZH_L16C_GF).

## Goals

- Validate the off-gassing seam against decotengu to tight per-compartment tolerance.
- Validate seeded deco (deco from a pre-saturated state) against decotengu.
- Validate `planTrip` end-to-end: a multi-dive trip's per-dive deco vs decotengu run as one
  continuous profile.
- Mirror the existing harness shape: a Python generator → checked-in JSON → a standalone JS
  comparison test with per-section stats and a non-zero exit on failure.

## Non-goals

- Wiring this into `npm test` (the 262-test suite). It stays a standalone, on-demand script
  like the existing decotengu test.
- Changing any `js/` engine code. This is test/validation only.
- A dense grid (the existing test has 3900 single-dive scenarios). Each trip here is a
  multi-dive continuous computation; ~60 total scenarios is enough and fast.
- Validating He (trimix) chaining. Air (N2-only) is the repetitive engine's domain today.

## Reference JSON shape

```json
{
  "generator": "decotengu 0.14.1",
  "model": "ZH-L16C",
  "surfacePressure": 1.01325,
  "n2Fraction": 0.79,
  "seamA_offgas": [
    { "startTissuesN2": [16 floats], "gapMin": 60, "expectedTissuesN2": [16 floats] }
  ],
  "seamB_seededDeco": [
    { "seedTissuesN2": [16 floats], "depth": 40, "bottomTime": 30,
      "gfLow": 100, "gfHigh": 100, "totalDeco": 17, "stops": [{ "depth": 6, "time": 5 }] }
  ],
  "trips": [
    { "gfLow": 100, "gfHigh": 100,
      "dives": [
        { "depth": 40, "bottomTime": 30, "siBeforeMin": null },
        { "depth": 30, "bottomTime": 30, "siBeforeMin": 60 }
      ],
      "perDiveDeco": [12, 21] }
  ]
}
```

Tissue vectors are 16 N2 partial pressures (bar), compartment order 1→16 (fast→slow), He
implied 0 (air).

## A. Python generator — `scripts/generate_decotengu_repetitive_reference.py`

Shared decotengu helpers (verify exact low-level signatures against the installed
`decotengu/engine.py` during implementation — the high-level `calculate(depth, time)` always
resets to surface, so the seeded/continuous paths use lower-level calls):

- `make_engine(gf_low, gf_high, gases)` → engine with `ZH_L16C_GF`, GF set, gases added.
- `surface_tissues(engine)` → `engine.model.init(engine.surface_pressure).tissues` (the
  surface-saturated seed; note `model.init` returns a `Data(tissues, gf)` namedtuple).
- `load_segment(engine, data, start_abs_p, end_abs_p, minutes, gas)` → advance tissues over a
  descent/ascent/constant segment via `engine.model.load(...)`, returning new `Data`. For a
  constant segment `start_abs_p == end_abs_p` and rate 0; for descent/ascent pass the
  pressure-change rate decotengu expects.
- `deco_from_seed(engine, seed_tissues, depth, bottom_time, gas_list)` → descend from the seed
  (load descent + bottom), construct a bottom `Step` carrying the loaded `Data`, run
  `engine._dive_ascent(step, deco_gas_list)` (which appends to `engine.deco_table`), and return
  `(stops, total, surfacing_tissues)`. `del engine.deco_table[:]` before each run. Determine the
  `Step` namedtuple fields from `Step._fields` and construct via `Step._make(...)` /
  `_replace(...)`.

**Seam A scenarios:** for a small grid of (dive1 depth, dive1 bottomTime) run a fresh decotengu
dive to obtain a realistic loaded surface state, then for each `gapMin` in {30, 60, 120, 240}
load the surface segment (`model.load(surface_p, gap, air, 0, data)`) and emit
`{ startTissuesN2, gapMin, expectedTissuesN2 }`. ~12–20 rows.

**Seam B scenarios:** reuse the post-SI states from Seam A (or freshly constructed seeds) as
`seedTissuesN2`; for a grid of (depth in {30,40,50}, bottomTime chosen to incur deco, GF in
{100/100, 40/85}) run `deco_from_seed` and emit `{ seedTissuesN2, depth, bottomTime, gfLow,
gfHigh, totalDeco, stops }`. ~12–20 rows. Skip any that produce 0 deco.

**Trip scenarios:** for ~20–30 trips (2-dive and a few 3-dive, depths {30,40,50}, SIs
{30,60,120,240}, GF {100/100, 40/85}) run one continuous computation: start from surface, and
for each dive `deco_from_seed(seed, depth, bottomTime)` → record `total` into `perDiveDeco`,
then load the next surface interval from the dive's `surfacing_tissues` to form the next seed.
Emit `{ gfLow, gfHigh, dives:[{depth,bottomTime,siBeforeMin}], perDiveDeco }`.

The generator prints `json.dumps(output, indent=2)` to stdout (the test reads the checked-in
file; regeneration is a manual `>` redirect, exactly like the existing generator).

## B. JS comparison test — `tests/decotengu-repetitive-comparison.test.mjs`

Mirror `tests/decotengu-comparison.test.mjs`: import from `js/`, `setZHL16Variant(ZHL16_VARIANTS.C)`,
load the reference JSON, run three comparison loops, print stats, `process.exit(1)` on any failure.

Air gas on our side is `{ id:'air', name:'Air', o2:0.21, n2:0.79 }` to match decotengu (as the
existing test does). Map decotengu tissue index `i` → our compartment via `COMPARTMENTS[i].id`
(assert `COMPARTMENTS.length === 16` and the same fast→slow ordering; if ordering differs, build
the mapping explicitly).

- **Seam A:** build a tissue dict from `startTissuesN2` (`{ [COMPARTMENTS[i].id]: v }`), run
  `simulateDepthTime(tissues, 0, gapMin, 0.79)`, compare each compartment to `expectedTissuesN2[i]`.
  Tolerance: absolute 0.001 bar per compartment (report the max abs diff across all scenarios).
- **Seam B:** build the seed dict from `seedTissuesN2`, call
  `generateDecoProfile(depth, bottomTime, [air], gfLow, gfHigh, undefined, { initialTissuePressures: seed })`,
  compare `totalDecoTime` to `totalDeco`. Tolerance `max(5, 0.20 * ref)` min.
- **Trips:** run `planTrip` on a trip built from the scenario (assign `startDateTime`s so the
  surface interval before each dive equals `siBeforeMin`; the first dive's `siBeforeMin` is
  null → place at t=0). For each dive compare `result.dives[k].profile.totalDecoTime` to
  `perDiveDeco[k]`. Tolerance `max(5, 0.20 * ref)` min.

Print, per section: passed/total, exact-match count, mean/median/P95/max abs diff, and up to 10
worst failures with their parameters. Exit non-zero if any section has a failure.

`generateDecoProfile` and `planTrip` are **synchronous** (plain `export function`s returning the
profile/result object directly — that is why `planTrip` consumes `generateDecoProfile` inline).
No `await` is needed; the Seam-B and trip loops are ordinary synchronous loops.

### Constructing trip `startDateTime`s from `siBeforeMin`

`planTrip` derives each surface interval from the real clock gap between a dive's start and the
previous dive's computed end. To hit a target `siBeforeMin`, the test must first know the
previous dive's end. Two options (pick during planning):
1. Iteratively: run `planTrip` with the dives placed far apart, read dive k-1's `endDateTime`,
   set dive k's `startDateTime = endDateTime + siBeforeMin`, re-run. A single forward pass
   suffices because each dive's end depends only on earlier dives.
2. Simpler/robust: place dive 0 at `t=0`; for k>0 set `startDateTime = (planTrip on dives
   0..k-1).dives[k-1].endDateTime + siBeforeMin`. Build the dive list incrementally.

Use option 2 (deterministic, no guessing of magic spacings).

## C. Expected agreement & tolerances

- **Seam A (off-gas):** should agree tightly (same half-times, same surface constants). 0.001 bar
  per-compartment tolerance; if the reported max diff is materially larger, that signals a
  constant/alveolar mismatch worth investigating (note it, don't loosen silently).
- **Seam B (seeded deco):** same `max(5, 20%)` as single-dive — seeded deco reuses the validated
  stop engine; the only new input is the initial tissue vector.
- **Trips:** same `max(5, 20%)`. Documented that dive1-ascent ±1-min stop rounding propagates
  into later dives' seeds, so end-to-end is necessarily looser than the seams.

The test is a **report + gate**, like the existing one: it prints agreement statistics and fails
only if a scenario exceeds tolerance. The headline number (e.g. "% within tolerance, max diff")
is the deliverable answer to "is the repetitive engine validated against decotengu?".

## Findings During Implementation (2026-06-16)

Running the first comparison surfaced two real divergences — exactly what the harness is
for. Both are resolved as documented model/scope decisions, not engine changes:

1. **Compartment 1 half-time (5.0 vs 4.0 min).** The off-gas seam showed every compartment
   matching decotengu to ~1e-16 **except** the fastest, which diverged up to ~8e-3 bar. Root
   cause: DecoJS uses the ZH-L16 **"1b"** first compartment (half-time **5.0 min**, Bühlmann's
   slightly-more-conservative alternative) while decotengu's `ZH_L16C_GF` uses the original
   **4.0 min**. This is a legitimate, intentional model choice in `tissueCompartments.js`, not a
   bug — and the off-gas seam is the only test sensitive enough to expose it (the fastest
   compartment rarely controls the deco the single-dive test compares). **Resolution:** Seam A
   excludes compartment index 0 from the tight 0.001-bar pass/fail check and reports its diff as
   informational, keeping the tight tolerance on the 15 compartments that use identical constants
   (which prove the off-gas integration is exact).

2. **300-min/stop cap on absurd profiles.** The original `depth+10` bottom-time grid produced
   unrealistic dives (e.g. 50 m for 60 min → 300–526 min of deco). One exceeded DecoJS's
   deliberate `DECO_STOP_MAX_MINUTES = 300` guard and threw `DecoCapExceededError`; decotengu is
   unbounded there. Notably, our engine matched decotengu **exactly** even on the in-range
   extremes (340 vs 339, 210 vs 210). **Resolution:** the grids use realistic recreational/
   light-tech bottom times `BT = {30: 25, 40: 18, 50: 14}` min, which keep every scenario inside
   the engine's usable range (verified: 0 cap errors, deco 6–37 min, agreement within 1–2 min).
   The test still wraps the deco calls in a guard that reports any future beyond-range scenario
   loudly rather than crashing.
